# Музична форма

Навчальний вебзастосунок для студентів 4 курсу фортепіанного відділу КМАМ ім. Р. Глієра. Статичний сайт (HTML, CSS, JS) без сервера, придатний для GitHub Pages.

## Як відкрити

**GitHub Pages:** Settings → Pages → Source: «Deploy from a branch» → гілка `main` (або робоча гілка), папка `/ (root)` → Save. Через хвилину сайт буде доступний за адресою, яку покаже GitHub.

**Локально:** відкрити `index.html` подвійним клацанням не вийде: браузер не дозволяє сторінці читати JSON-файли з диска. Потрібен простий вебсервер, наприклад:

```bash
python3 -m http.server 8000
# потім відкрити http://localhost:8000
```

## Структура

```
index.html            — сторінка застосунку
assets/app.css        — оформлення (світла й темна тема, телефон)
assets/app.js         — логіка: розділи, приклади, завдання, прогрес
data/sections.json    — перелік розділів курсу і загальні примітки
data/section-1.json   — розділ 1 «Елементи форми»
data/section-2.json   — розділ 2 «Період»
verification-report.md — звіт для викладача: джерела, перевірка прикладів, розбіжності
```

## Як редагувати контент

Увесь текст — у файлах `data/section-N.json`. Після зміни файлу достатньо оновити сторінку.

### Теорія (`theory`)

Кожен блок має поля:
- `term` — назва поняття;
- `definition` — визначення;
- `source` — джерело (обов'язкове: «Конспект» або автор і параграф);
- необов'язкові: `motto` (виділений рядок), `points` + `pointsSource` (пункти та їхнє джерело), `steps` (нумерований перелік), `scheme` (схема літерами), `table` (рядки з `name`, `formula`, `text`, `source`), `list` (рядки з `name`, `text`, `source`).

### Приклади (`examples`)

```json
{
  "id": "ex-op14-1",
  "topic": "Дроблення (8 = 4 + 2 + 2)",
  "composer": "Л. ван Бетховен",
  "work": "Соната № 9 E-dur, op. 14 № 1",
  "part": "III частина, Rondo. Allegro comodo",
  "bars": "тт. 1–8",
  "edition": "Breitkopf & Härtel, «Beethovens Werke», Serie 16",
  "imslp": "https://imslp.org/wiki/…",
  "analysis": "Текст аналізу",
  "ruler": { "start": 1, "groups": [ { "len": 4, "label": "4" }, { "len": 2, "label": "2" } ] },
  "source": "Способин, § 29, приклад 66"
}
```

`ruler` — лінійка тактів під прикладом: кожна група — `len` тактів з підписом `label`. Поле можна не вказувати.

Додавати в застосунок можна лише приклади, затверджені у звіті `verification-report.md`. Посилання — тільки на сторінки творів в IMSLP.

### Завдання (`tasks`)

Спільні поля: `id` (унікальний у розділі), `type`, `q` (питання), `explain` (пояснення, яке студент бачить після відповіді).

| `type` | Що вказати |
|---|---|
| `single` | `options` — варіанти; `answer` — номер правильного (з нуля) |
| `multi` | `options`; `answer` — масив номерів правильних |
| `match` | `pairs` — пари `["ліве", "праве"]` у правильній відповідності; праві частини перемішуються автоматично |
| `order` | `cards` — картки в правильному порядку; `distractors` — зайві картки |
| `bars` | `fields` — поля `{ "label": "…", "answer": 8 }` |
| `error` | `statements` — твердження аналізу; `answer` — номер помилкового |

Прогрес студента зберігається в `localStorage` браузера (ключ `muzforma.progress.v1`). Якщо змінити `id` завдання, збережена відповідь на нього зникне.

## Правила тексту

- Долі такту — словом: «перша доля», «друга доля».
- «Подвійні варіації» — лише у значенні «варіації на дві теми».
- Біля кожного визначення — джерело.
